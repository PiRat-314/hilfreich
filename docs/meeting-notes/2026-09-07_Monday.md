## Reason for the Project

This is a project for matching people up who request assistance,
with people with the skills and time
who are capable of providing that assistance.

Right now, there is one person handling requests for assistance,
and these requests are all effectively maintained in that person's head.
We need a better way to make sure that:

1) Requests don't have to be managed entirely by one person.
   The app should support multiple people being able to manage it.
2) Requests can be tracked for status,
   (e.g., looking for volunteers, matched, completed, etc.)
3) Information related to the request can be stored together,
   and not just in emails that only one person has access to.

## First Version

An ideal version of the project might include some kind of frontend
where volunteers and help-seekers can register themselves
and be included in conversations surrounding the requests
they're affiliated with.

However, for the first version,
we're only trying to replace the existing "in someone's head" system.
The only users of the system will be:

1) A primary non-technical request manager.
2) Multiple request organizers that can manage delegated requests,
   but not administer permissions.

(Jay note #1:
Volunteer organizations often have people come and go at short notice.
While there should be at least one mandatory request administrator,
it should not be a system that hard-codes it to only one.
It's important to have redundancy,
so another person can take over if someone is suddenly unavailable.)

(Jay note #2:
We may also want to have a technical administrator as a separate role.
We should not expect the main request administrator to have a technical background.
This technical administrator ideally would have access to app settings,
but minimal access to user data or permissions.
Not required for an MVP;
just something to consider if we notice the app requires a lot of configuring.)

### Must-Haves for the First Version

* User management tools
* Request/ticket/issue support
  * Easy creation form
  * Status
  * Additional information after request/ticket/issue creation
* Organizer support on request/tickets/issues
  * Type of job
  * Timeline/deadline
  * What type of help is necessary?
    * People
    * Vehicles, tools, etc.
  * Easily extensible fields/tags to cover things we didn't think of
  * Search/filter (e.g., region? open/closed)
* German Language Support

## Eventual Features (Not In First Version)

* Volunteer member registration with filters
  * Task type
  * Locations
  * Transport
* Web form for member request submissions
* Messaging service inside web app:
  * Organizers to requestors/volunteers
  * Managers to organizers and organizers to each other

### Software Exploration

Ideally we'd like to code as little from scratch as possible,
in order to get this running quickly.
This could mean:

* Using an existing service.
* Piggy-backing off of existing open-source software
  with a good API that allows us to customize/extend it later.

Some software that kind of feels like what we might want:

* Gitlab
* Bulletin Board/Forum
* CRM
* Kanban

Also, looking forward to a time when non-managers may make their own requests,
we might want a frontend for requestors/volunteers with a bit of a Freecycle vibe.
